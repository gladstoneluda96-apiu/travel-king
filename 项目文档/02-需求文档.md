## 1. 背景与目标

规划一次旅行需要在多个平台之间来回切换：找攻略、翻游记、查天气、比酒店、算预算、排路线，信息过载且决策疲劳。本项目把这些环节收敛到一个界面：**用户只描述目的地与偏好，系统产出一份可直接执行的行程方案**。

目标：

1. 单次提交后自动完成「景点筛选 → 天气 → 酒店 → 预算 → 路线 → 可视化」全流程。
2. 方案不止是列表，而是可核对的行程：景点有地址与时长、交通有建议、餐饮有推荐、门票有价格、需要预约的景点要显式提醒。
3. 生成后仍可追问细节（AI 问答），并能导出长图分享。
4. 本地可一键部署，密钥与数据都留在本机。

## 2. 用户与场景

| 角色 | 场景 | 关注点 |
| --- | --- | --- |
| 自由行游客 | 计划一次 2～5 天国内游 | 景点是否值得去、路线是否绕路、预算是否可控 |
| 多城市出行者 | 一次出行串多个城市 | 每个城市停留天数、城际交通日、总天数联动 |
| 带长辈/带娃出行者 | 行程节奏是否合适 | 单日景点数量、游览时长、是否需要预约 |
| 项目维护者 | 本地部署与二次开发 | 一个服务能起来、密钥可运行时替换、日志可查 |

## 3. 功能需求

优先级：P0 必须交付 / P1 应交付 / P2 可选。

### FR-01 行程生成（P0）

- **描述**：用户提交目的地、日期、天数、交通方式、住宿偏好、兴趣标签与补充需求后，系统异步生成完整行程。
- **输入**：`city` 或 `cities[]`、`start_date`、`end_date`、`travel_days`、`transportation`、`accommodation`、`preferences[]`、`free_text_input`、`language`。
- **输出**：任务 `task_id`，随后可查询到包含逐日行程、预算、天气、知识图谱的结果。
- **验收标准**：提交后前台能持续看到分阶段进度（搜索景点 → 查询天气 → 生成计划）；任务完成时返回可渲染的结构化行程；单次生成耗时在数分钟内且不会因超时中断。

### FR-02 多城市行程（P0）

- **描述**：支持在一次行程中添加多个城市并分别设置停留天数，总天数自动汇总。
- **验收标准**：可添加/删除城市；总天数 = 各城市之和；城际移动日有明确交通建议；预算中城际交通单独统计。

### FR-03 偏好与特殊需求（P1）

- **描述**：兴趣标签（历史文化、美食、自然风光等）可多选；提供自由文本补充需求。
- **验收标准**：所选偏好体现在行程内容中；标签为可点选的胶囊控件，选中态清晰。

### FR-04 景点素材检索与提纯（P0）

- **描述**：从真实游记中检索景点，提纯为结构化数据（名称、推荐理由、建议时长、是否需要预约及预约提示），并补齐经纬度坐标。
- **验收标准**：景点带真实地址与坐标；需要预约的景点显式标注；坐标来自地理编码而非模型臆测（地理编码失败时允许降级但需可识别）。

### FR-05 天气信息（P0）

- **描述**：按城市的行程日期查询天气（白天/夜间天气、气温、风向风力）。
- **验收标准**：天气数据来自高德接口；同一天多城市分别展示；数据缺失时有明确占位而非空白。

### FR-06 酒店推荐（P1）

- **描述**：按住宿偏好检索酒店/民宿并给出区域与价格建议。
- **验收标准**：酒店信息来自高德 POI 检索；预算面板体现住宿费用。

### FR-07 预算明细（P0）

- **描述**：汇总门票、餐饮、住宿、交通与城际交通，给出总计。
- **验收标准**：各分项可展开查看明细；分项之和等于总计；数字使用等宽字体便于对齐比较。

### FR-08 景点地图（P0）

- **描述**：在高德地图上按真实经纬度绘制「起点 → 景点 → 终点」标记与连线。
- **验收标准**：地图可加载真实瓦片；标记数量与景点数量一致；主题切换时底图同步切换；地图不可用时不影响其他模块。

### FR-09 每日行程（P0）

- **描述**：按天展示景点顺序、游览时长、交通方式、餐饮安排与住宿建议。
- **验收标准**：每天可展开/收起；景点顺序与地图标记一致；含预约提醒与防坑建议。

### FR-10 知识图谱可视化（P1）

- **描述**：将「城市 → 天数 → 景点/餐饮/住宿/预算」的层级关系渲染为可交互图谱。
- **验收标准**：节点分类着色统一；可拖拽、可缩放；悬停显示节点详情；主题切换后配色同步。

### FR-11 沉浸式 AI 问答（P0）

- **描述**：生成行程后提供悬浮问答面板，AI 具备完整行程上下文。
- **验收标准**：可对行程细节追问（票价、适宜性、交通）；回答引用行程中的实际信息；提供快捷提问；加载态与网络异常有明确反馈。

### FR-12 历史记录（P1）

- **描述**：展示最近生成的行程，可再次打开。
- **验收标准**：列表展示城市、日期范围、天数与更新时间；点击可回到对应行程；服务重启后历史仍在。

### FR-13 攻略图导出（P2）

- **描述**：把行程导出为一张长图，便于分享。
- **验收标准**：包含行程、预算、地图、天气、酒店等主要板块；图片可正常保存。

### FR-14 多语言（P1）

- **描述**：界面与生成的行程数据支持中文、英文、日文切换。
- **验收标准**：切换语言后界面文案与行程输出语言同步；品牌名在三语下均正确显示。

### FR-15 日间 / 夜间主题（P1）

- **描述**：默认跟随系统主题，用户可手动切换，选择需持久保存。
- **验收标准**：切换即时生效且不闪白；地图底图、知识图谱配色同步；重新打开页面保持上次选择；两种模式下文字对比度均达到 WCAG AA。

### FR-16 运行时配置（P1）

- **描述**：无需改文件即可在界面内配置 LLM、高德、小红书等凭据。
- **验收标准**：敏感字段以掩码返回；保存后立即生效（无需重启）；再次打开时掩码不被覆盖为明文。

### FR-17 用户偏好记忆（P2）

- **描述**：可选开启，从行程中提取稳定偏好并加权存储，下次规划时召回注入。
- **验收标准**：开关可控；支持查看、手动添加、删除与清空；可选 SQLite 持久化。

### FR-18 本地一键部署（P0）

- **描述**：提供一键启动方式，包含依赖自检与首次运行自动装配。
- **验收标准**：双击脚本即可启动并自动打开页面；重复执行不会重复启动；停止/重启/查看状态可用；开机自启。

## 4. 非功能需求

| 编号 | 类别 | 要求 | 当前达成情况 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 页面可交互时间可控；接口响应不阻塞界面；长任务不触发网关超时 | 异步任务 + 轮询/WebSocket 已达成；首屏包体仍有优化空间 |
| NFR-02 | 稳定性 | 服务异常自动重启；单次请求失败不导致整页不可用 | LaunchAgent `KeepAlive`；地图/天气/配图均可降级 |
| NFR-03 | 可访问性 | 全页文字对比度 ≥ WCAG AA；键盘可操作；尊重减弱动效 | 实测最低对比度 5.03～5.89；提供焦点环与 reduced-motion 降级 |
| NFR-04 | 安全 | 密钥不入库、不外泄；图片代理限定域名；配置接口掩码返回 | `.env` 已加入 gitignore；代理域名白名单；密钥掩码 |
| NFR-05 | 可维护性 | 样式令牌化、模块职责单一、命名一致 | 已建立令牌层与组件边界 |
| NFR-06 | 兼容性 | 现代浏览器；移动端可读可用 | 1440 / 768 / 375 三档视口无横向溢出 |
| NFR-07 | 成本 | 单次行程生成的 LLM 调用成本可控 | 默认使用轻量模型（同量级输出 22s 与原模型 67s 对比） |
| NFR-08 | 可观测性 | 关键流程有日志；图源与降级路径可追溯 | 服务日志含阶段进度、图源来源、限流冷却提示 |

## 5. 范围边界（本期不做）

- 不做用户账号体系与云端多租户；数据仅保存在本机。
- 不做在线支付、门票代订、酒店下单。
- 不做移动端原生应用（仅 Web 响应式）。
- 不做自动发布到社交平台。
- 不复刻小红书全文内容，仅使用检索到的公开素材摘要与图片。
